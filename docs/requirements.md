## 1. 背景与目标

### 1.1 项目总体目标（从设计文档 §1 迁入）

- **开源、公益**，暂不考虑任何商业诉求
- **核心支持中文与英文**，其他语言暂不保证质量。第一阶段所说的「中文」**优先保障现代白话**的质量。繁体中文书籍在朗读前自动转换为简体（只转换送给 TTS 的文字，原文不变），与简体书同等对待；文言或古白话成分较多的作品（如《红楼梦》），以及夹杂古文词汇的白话文，可能读错字或漂移到方言口音，这是 TTS 模型本身的问题，不在第一阶段的质量目标内（§9.1 Q18、Q20）
- 许可证 **Apache-2.0**
- 差异化定位：**中文优先 + Apple Silicon 本地 TTS（MLX）+ LLM 多角色剧本化 + 标准有声书封装**（设计文档 §4.3）

### 1.2 场景路线图

| 优先级 | 场景 | 阶段 |
|---|---|---|
| **P0** | **小说有声书** | **第一阶段，本文档范围** |
| P1 | 单人 / 多人播客音频制作 | 后续 |
| P2 | 复杂网页朗读 | 后续 |
| P3 | 学术论文（PDF）朗读 | 后续 |

**范围纪律**：P1–P3 在第一阶段只体现在 Script IR 的 block type 设计中，不写任何实现代码（理由见设计文档 §1.3）。

### 1.3 第一阶段目标（一句话）

**用户在一台 Apple Silicon Mac 上，把一本中文或英文小说（TXT / EPUB）交给 `huashuo`，得到一个可直接导入 Apple Books / Audiobookshelf 等播放器的 M4B 文件：章节可跳转、元数据与封面齐全、旁白与主要角色由不同且合适的声音演绎、全书音量一致、没有漏读错读的整段文字。**

其中「旁白与主要角色由不同的声音演绎」原为**条件 P0**，取决于内置音色库能否达到质量关卡（§6、§9.1 Q1/Q2）。**EXP-1 已于 2026-09-24 通过关卡**（§9.1 Q16），多角色是第一阶段的 P0。**多角色只针对中文书**：英文音色库推迟到第二阶段，第一阶段的英文书由旁白音色朗读全书，包括对白（§9.1 Q19）。

「精心制作」具体指（第一阶段对「好」的定义）：

1. **结构正确**：章节与原书一致，章节名可读，播放器里能跳转
2. **内容完整**：原文每一个字都被读到，且只读一次；不读目录、版权页等非正文
3. **角色可辨**：旁白与主要角色声音不同，同一角色全书同一把嗓子，声音与角色的性别年龄相称
4. **听感舒适**：音量一致、停顿自然、没有爆音和明显的合成事故（复读、截断、静音）
5. **可修正**：说话人判错、读音错误、选角不满意时，用户能改一个文件然后只重跑受影响的部分

### 1.4 目标用户

- 想把自己手上的电子书（尤其是中文网文、经典小说）转成有声书自己听的个人用户
- 有一台 Apple Silicon Mac（M1 及以上），能使用命令行，愿意配置一个 LLM API Key（云端或本地）
- 不要求懂 TTS / LLM 原理；但愿意在需要时手工编辑一个结构清晰的文本文件（剧本 / 选角表）

## 2. 用户流程

```
huashuo book.epub
  ① 导入    解析文件 → 提取正文、章节、元数据、封面            （本地，秒级）
  ② 预估    显示章节数、字数、预计 LLM 费用、预计合成时长、磁盘占用  （本地，秒级）
  ③ 剧本化  LLM 抽取角色 + 批量标注说话人 → 生成「剧本」+「选角表」 （LLM，分钟级）
  ④ 审阅    （可选）用户查看/修改剧本与选角表，试听每个角色的声音
  ⑤ 合成    逐 block 合成，可中断、可续跑                         （本地，小时级）
  ⑥ 封装    后期处理 + 章节标记 + 元数据 + 封面 → book.m4b          （本地，分钟级）
```

两种使用方式都必须支持：

- **一条命令跑到底**：①–⑥ 自动执行，④ 跳过（需求 `CLI-2`）
- **分步执行**：每一步可单独运行，④ 之后的修改只触发必要的重算（需求 `CLI-3`、`SYN-3`）

## 3. 功能需求

### 3.1 输入与解析（IN）

| 编号 | 需求 | 优先级 |
|---|---|---|
| IN-1 | 支持 **TXT** 输入，自动识别编码：UTF-8（含 BOM）、GB18030 / GBK、UTF-16；识别失败时明确报错，不静默乱码 | P0 |
| IN-2 | 支持 **EPUB**（2 与 3）输入：按 spine 顺序读取正文，利用目录（NCX / nav）辅助章节划分 | P0 |
| IN-3 | 从 EPUB 提取**元数据**（书名、作者、语言、出版者、简介、出版日期）与**封面图** | P0 |
| IN-4 | TXT 无元数据时，从文件名与正文开头推断书名/作者；允许用命令行参数（`--title`、`--author`、`--cover`）覆盖书名、作者和封面，重新导入时沿用。配置文件不在第一阶段 | P0 |
| IN-5 | **语言自动识别**（中文 / 英文），可手动指定；决定章节规则、分句规则、TTS 语言参数 | P0 |
| IN-6 | 中文书名、中文路径、带空格/特殊字符的路径全程可用（设计文档附录 B 的前三项陷阱不得重现） | P0 |
| IN-7 | 支持 MOBI / AZW3 / FB2 等其他电子书格式（可借 calibre `ebook-convert` 转成 EPUB 后处理） | P2 |
| IN-8 | 支持文本型 PDF 小说 | P2 |

### 3.2 文本清洗与结构识别（TXT）

| 编号 | 需求 | 优先级 |
|---|---|---|
| TXT-1 | **章节识别（中文）**：「第X章/回/卷/部/节/集」（中文数字与阿拉伯数字）、楔子、序章、序言、尾声、终章、番外；支持网文无分隔符标题（「第一章陨落的天才」）；不误伤正文中的「他第一章都没看」 | P0 |
| TXT-2 | **章节识别（英文）**：Chapter / CHAPTER + 数字或英文序数或罗马数字、Prologue、Epilogue、Part、Book 等 | P0 |
| TXT-3 | **卷 / 章两级结构**：识别「第一卷 xxx」下的章节；M4B 章节名体现所属卷（如「第一卷 · 第三章 风起」），因为多数播放器只支持单层章节 | P1 |
| TXT-4 | **去除非正文**：目录页、版权页、EPUB 中的导航页、重复的书名页等不进入朗读 | P0 |
| TXT-5 | **网文噪声清理**：常见的「求月票/求推荐票」、作者感言、「本章完」、站点水印与广告行，可识别并标记为 `skip`（不删原文，只是不读） | P1 |
| TXT-6 | **引号识别**：`“”`、`「」`、`『』`、`""`、`''`，以及嵌套引号；归一化规则全书一致（设计文档附录 B 最后一项陷阱不得重现） | P0 |
| TXT-7 | 全角/半角标点、空白、换行的规整：中文正文用全角标点，英文与数字用半角；借助成熟的 Unicode 库覆盖尽可能完整的中文标点（设计文档 §10.2）；不在中文里补半角句号 | P0 |
| TXT-8 | 识别结果可在执行 ③ 之前通过 `--dry-run` 查看：章节列表（标题 + 字数）、被跳过的内容 | P0 |
| TXT-9 | **编辑注释**：「注釋 / 注释 / 附注 / 译者注」等标签及其后直到下一章的内容标记为 `skip`（reason `notes`）；`--read-notes` 改为朗读，选择记在工作目录里 | P1 |
| TXT-10 | **Project Gutenberg 声明**：`*** START/END OF THE PROJECT GUTENBERG EBOOK ***` 之外的首尾声明标记为 `skip`（reason `license`） | P1 |
| TXT-11 | **从纯文本转换的 EPUB**：标记为标题、目录标签的内容必须「像标题」（短、不含句末标点、不以冒号结尾）才当标题；按固定宽度硬换行的正文先合并回段落；没有编号的篇名（短篇集）可识别为章节 | P1 |

### 3.3 剧本化（SCR）

剧本（Script IR）是第一阶段的核心产物。格式名为「**话本**」，文件为 **JSONL**，扩展名 `*.huaben.jsonl`（§9.1 Q5；schema 在单独的 Script IR 设计文档中定义，设计文档 §8.3）。

| 编号 | 需求 | 优先级 |
|---|---|---|
| SCR-1 | 生成**人可读、可手改**的剧本文件：JSONL，一行一个 block；每个 block 有类型（chapter / heading / narration / dialogue / skip …）、文本、说话人（dialogue）、原文位置。写出时不转义非 ASCII 字符、字段顺序固定，保证能直接阅读和 diff | P0 |
| SCR-2 | **旁白与对白切分**：一行里「他说："你好。"然后走了」拆成旁白 / 对白 / 旁白；对白标签（「他说」）归入旁白 | P0 |
| SCR-3 | **角色抽取**：全书扫描得到角色表，每个角色含规范名、别名、性别、年龄段、简短性格/声音描述、出场次数 | P0 |
| SCR-4 | **别名归并**：「苏姑娘 / 苏晚晴」「贾宝玉 / 宝玉 / 宝二爷」合并为一人；「萧战 / 萧炎」这种同姓不同人不得误合并 | P0 |
| SCR-5 | **说话人归属**：每一句对白归到角色表中的一个角色或「未知」；要能处理前置/后置/省略的对话标签、前向引用、被旁白打断的连续对白（设计文档 §3.2 的四类难例）。**「未知」一律由旁白声音朗读**，不设单独的兜底声音（§9.1 Q10） | P0 |
| SCR-6 | **段落级批量标注**：LLM 只输出「索引 → 说话人」，不回显原文；分块带重叠（设计文档 §7.2） | P0 |
| SCR-7 | **对账**：正则得到的对白行清单与 LLM 输出逐一核对，漏答、幻觉索引、未知角色名都要被发现并补问或标记；剧本拼接后的文本必须与清洗后的原文**逐字一致** | P0 |
| SCR-8 | **不改写原文**：LLM 只做标注，不产出要朗读的文字；任何改写（如读音替换）都是显式、可追溯的 hint | P0 |
| SCR-9 | **第一人称小说**：识别以「我」为叙述者的小说，允许旁白使用主角的声音（或由用户选择） | P1 |
| SCR-10 | 用户**手改剧本后重跑**，已改部分不被 LLM 结果覆盖 | P0 |
| SCR-11 | **低置信度标注可见**：列出模型不确定的归属与所有「未知」说话人，方便用户优先审阅 | P1 |
| SCR-12 | **情绪/语气提示**：为对白标注情绪（如「惊恐」「低声」），合成时作为 TTS `instruct` 使用。情绪标签与说话人在同一次批量标注中产出（SCR-6），不额外调用 LLM；可整体关闭。EXP-1 验证了注入音色支持 instruct，且情绪变化时的音色漂移在可接受范围内（设计文档 §5.6）；默认只使用程度适中的情绪描述，避免强烈情绪带来的音色变化 | P1 |
| SCR-13 | **无 LLM 模式**：不配置 API Key 时仍可产出单音色有声书（只做章节与分段，不做角色） | P0 |

### 3.4 选角与音色库（CAST）

**音色来源：内置音色库**（§9.1 Q2）。项目预先设计、筛选并随项目发布一套**与输入无关**的固定音色，所有书都从这个库里选角；不在每本书处理时临时设计声音。

| 编号 | 需求 | 优先级 |
|---|---|---|
| CAST-1 | **内置中文音色库**：随项目发布 12–20 个经人工筛选的中文角色音色，覆盖常见角色类型（男/女 × 儿童/少年/青年/中年/老年，同一类型内有音色差异，如「清朗 / 低沉」）。每个音色带结构化标签（性别、年龄段、音色特征、适用角色）。全部为标准普通话，无方言口音 | P0 |
| CAST-2 | **内置英文音色库**：同样的方式为英文建库，前提是英文音色通过一轮与 EXP-1 相同的检验。**推迟到第二阶段**（§9.1 Q19）；第一阶段的英文书由旁白音色朗读全书，包括对白 | 第二阶段 |
| CAST-3 | **音色稳定**：同一库音色在任何书、任何句子上听起来是同一个人；库音色的生成方式固定、可复现（设计文档 §5.6） | P0 |
| CAST-4 | **旁白音色**：默认使用专为旁白设计的库音色（中文女旁白 `narrator_female`，另有男旁白 `narrator_male`；英文暂用预置 `ryan`）。按书自动选择：第一人称的书按叙述者的性别，否则按明显的主角的性别，其余用默认（设计文档 §5.11）；`--narrator female\|male\|<音色>` 或手改 `cast.json` 覆盖；旁白音色不分给角色（§9.1 Q3）；章节标题与开场/结尾报幕也使用旁白音色（§9.1 Q7） | P0 |
| CAST-5 | **按角色画像自动选角**：用完整画像（性别 + 年龄段 + 描述）匹配库音色标签，不把画像压成单一分数（设计文档 §3.3 的撞车问题不得重现） | P0 |
| CAST-6 | **主要角色不撞声**：出场最多的前 N 个角色互不相同，且都不同于旁白。N 默认 8，上限受库中同性别同年龄段的音色数约束；约束冲突时，出场少的角色先共享 | P0 |
| CAST-7 | **次要角色共享声音**：按性别/年龄段复用库音色，但连续对话的两个角色不应同声 | P1 |
| CAST-8 | **同一角色全书一致**：跨章节、跨续跑、跨重新合成，同一角色的声音不漂移 | P0 |
| CAST-9 | **默认排除方言音色**（Qwen3-TTS 预置的 `dylan` 北京话、`eric` 四川话；设计文档 §5.2、§5.6）；用户可显式选用。2026-09-26 起**所有预置音色都不参与自动选角**：`serena` 会漂移到陕西口音（盲听 12 次中 3 次），自动选角只用经过口音试听的库音色（Q21） | P0 |
| CAST-10 | 生成**可编辑的选角表**：角色 → 音色，用户可改；修改后只重合成该角色的 block | P0 |
| CAST-11 | **试听**：为每个角色（或指定角色）用其一句真实台词生成样音，便于在长时间合成前确认选角；也可列出并试听整个音色库 | P0 |
| CAST-12 | **按书设计新音色**：用户为某个角色写声音描述，临时设计一个库外音色，固化后在该书中复用 | P2 |
| CAST-13 | 用户提供参考音频为某个角色**克隆声音**（需用户自行确保有权使用该声音） | P2 |

### 3.5 读音与文本归一化（PRON）

| 编号 | 需求 | 优先级 |
|---|---|---|
| PRON-1 | **读音词典**：用户可为人名、地名、专有名词指定读音或替换文本（如「单于 → chán yú」「重楼」），全书生效；保存在工作目录的 `pron.txt` 中，不改原文、可追溯（M5 实现时由「剧本 hint」改为独立文件，理由见设计文档 §10.3） | P1 |
| PRON-2 | **数字、日期、单位、符号**的读法按语境处理（「1998年」「第3名」「5%」「3:2」） | P1 |
| PRON-3 | 中文书里的英文单词/缩写、英文书里的中文名，能以合理方式读出 | P2 |
| PRON-4 | 多音字错误可通过 PRON-1 的机制逐个修正（不要求自动消歧） | P1 |

### 3.6 合成（SYN）

| 编号 | 需求 | 优先级 |
|---|---|---|
| SYN-1 | 默认引擎 **Qwen3-TTS 1.7B**，经 mlx-audio 在本机运行；模型可配置（0.6B / 量化位数） | P0 |
| SYN-2 | **TTS 引擎是插件接口**：剧本不依赖具体引擎；第一阶段只需实现 Qwen3-TTS，但接口不能假设 HTTP | P0 |
| SYN-3 | **按合成单元内容哈希缓存**：key 包含朗读文本、音色、instruct、模型与采样参数；改一个 block 只重合成它所在的单元（Script IR 设计 §6） | P0 |
| SYN-4 | **断点续跑**：任意时刻中断（Ctrl-C、断电、崩溃）后继续，已完成部分不重做、不损坏 | P0 |
| SYN-5 | **可复现**：同样输入与参数重跑，得到一致的音频（续跑不产生音色漂移） | P0 |
| SYN-6 | **结果校验与重试**：检测空输出、截断、复读失控、时长与字数严重不符；自动重试，仍失败则保留并在最后汇总报告，不中断整本 | P0 |
| SYN-7 | **进度与预计剩余时间**：按字数/时长显示整体与当前章节进度 | P0 |
| SYN-8 | 在内存允许时利用批量生成提升吞吐（mlx-audio `batch_generate`） | P2 |
| SYN-9 | 按章节优先级合成：可先只合成指定章节（如第 1 章）用于整体试听 | P1 |
| SYN-10 | **ASR 校验（可选）**：每个合成的 block 用语音识别转写，与原文比对字错率；发现漏字、错字、复读时换 seed 重新合成（次数有上限），仍不通过则按 SYN-6 保留并报告。**默认开启，用户可关闭**以省下约 5–10% 的合成时间；首次使用时下载 ASR 模型（约 2 GB）。比对时忽略标点与同音异写（如「师父 / 师傅」），阈值可配置 | P1 |

### 3.7 音频后期（POST）

| 编号 | 需求 | 优先级 |
|---|---|---|
| POST-1 | **响度统一**：全书（含不同声音之间）响度一致，默认积分响度 **-18 LUFS**，可配置（§9.1 Q6） | P0 |
| POST-2 | **峰值控制**：真峰值默认 **≤ -1.5 dBTP**，无削波爆音；以前瞻限幅器只处理少数尖峰，响度仍达到目标 | P0 |
| POST-3 | **停顿设计**：段落之间、同段内换说话人、场景分隔（`***`、空行）、章节标题前后使用不同的停顿时长；单个 block 可用 `pause_after` 覆盖。M1 为固定默认值（Script IR 设计 §6），可配置留待 M4 | P0 |
| POST-4 | **首尾静音修整**：去除每个片段首尾多余的静音，再按 POST-3 统一插入 | P1 |
| POST-5 | **章节标题朗读**：每章开头用旁白音色读出章节名（如「第一章，风雪山神庙」），可关闭 | P0 |
| POST-6 | **开场与结尾**：书开头用旁白音色读出书名与作者（可选附加「本有声书由话说 Huashuo 生成」），结尾有收束提示；均可关闭 | P1 |
| POST-7 | 拼接时采样率、声道、编码参数全书一致（设计文档 §8.5 的静音拼接坑不得重现） | P0 |

## 5. 质量验收标准

第一阶段以一组**固定的验收语料**为准。验收在 M5 之后进行（§6「第一阶段验收」），由项目负责人准备真实小说并执行；开发中用模拟测试文件覆盖相同的功能。

### 5.1 验收语料

| 语料 | 语言 | 用途 |
|---|---|---|
| 设计文档 §3.2 的 40 行中文样本 | 中 | 说话人归属难例回归 |
| **《一条被洗澡水拍死的鱼》**（半轻人，约 9,500 字，CC BY-NC-ND 4.0，`examples/fish/`，TXT 与 EPUB 两种格式） | 中 | 仓库内的金标准：两种格式结果一致、结构、第一人称旁白、说话人归属（作者核对的 `speakers.tsv`，≥95%；LLM 回答随仓库保存，测试离线重放）；公开发布时的 README 演示 |
| **简体中文现代白话长篇小说**（首选测试文本；如格非《春尽江南》，约 21 万字。版权原因只在本地使用，不进仓库） | 中 | 朗读质量（普通话、读音）、章节、角色、别名、长书的耗时与费用 |
| 一部网文风格 TXT（GBK 编码，含卷结构与噪声行） | 中 | 编码、卷章、噪声清理 |
| 一部公版英文小说 EPUB（Project Gutenberg，如 *Pride and Prejudice*） | 英 | 英文章节、对白与说话人归属、别名（"Mr. Darcy / Darcy / Fitzwilliam"）；第一阶段英文书只用旁白音色（Q19） |
| 一部第一人称小说 | 中或英 | SCR-9 |

其中说话人归属部分需要人工标注，同时作为 LLM-6 的文本分析质量基准。EXP-2 的《孔乙己》基准是繁体字，只用于检验说话人归属（LLM 读繁体没有问题），不作为朗读质量的测试依据。

繁体中文（如 Project Gutenberg 的鲁迅《吶喊》）与古典小说不作为朗读质量的测试依据：M1 实测中它们的错读与口音漂移明显多于现代简体文本（设计文档 §5.8）。

### 5.2 量化指标

| 指标 | 门槛 |
|---|---|
| **文本完整性**：清洗后正文 vs 剧本拼接文本 | **逐字一致**（0 差异） |
| **章节识别**：与人工标注对比 | 验收语料上 100% |
| **说话人归属准确率**：人工标注的对白 | ≥ 95%（中文 40 行样本 100%）；目标值在基准建立后复核 |
| **主要角色撞声**（多角色版本） | 0 |
| **合成事故率**（校验失败且重试后仍失败的 block） | ≤ 0.1%，且全部出现在报告中 |
| **响度** | 全书积分响度偏离目标 ≤ 1 LU；章节之间偏差 ≤ 1 LU |
| **播放器兼容** | Apple Books 通过（M4B-5；其他播放器在 M6） |

### 5.3 主观验收

- 随机抽 3 章，由至少一名听众完整试听，对「角色可辨」「停顿自然」「没有明显错读」给出通过/不通过
- 记录发现的问题，归入 PRON / POST / SCR 需求的回归用例

**完成情况**：全部条目已实现，测试 202 个。本阶段真实 LLM 的花费共 $0.015（一次第一人称短篇的检验）；其余检验都用缓存或模拟模型。

- **读音词典**：`pron.txt`，读法可以是同音字或带声调符号的拼音（实测 Qwen3-TTS 把拼音读成汉语音节，声调大多正确；声调数字会被读成数字，所以自动换成符号）；规划单元时替换，改了直接重新合成，只重做含这些词的单元；导入时报告每个词条匹配了几次
- **数字**：实测 Qwen3-TTS 自己能读对年份、数量、百分比、比分、时刻、日期、小数、电话、单位、分数、货币、范围；只为读错的三类（「-5℃」丢负号、区号横线读成「到」、「No.1」）加读法。ASR 比对改为两边都换成阿拉伯数字，并把 ℃、km、1/3、¥、3:2、8:30 等写成读出来的样子；22 句数字实验中读对的都以 0% 通过
- **网文噪声**、**开场与结尾**、**清理缓存**（`huashuo clean`）、**故事集篇名前缀**、**英文单引号对白**、**方言句末误判**：见 §6.4 各条；在《春尽江南》《白夜行》《吶喊》上核对过没有误伤（噪声规则 0 误判；篇名规则只改变《吶喊》的阿Q正傳）
- **配角借用主要角色的音色**：采用。只有一两句台词、且从不与该主要角色同章出现的配角可以借用；《春尽江南》上最拥挤的三个音色由各 24、24、23 人降到 12–13 人
- **第一人称**：真实 LLM 检验发现叙述者常被标成真名（「林默」，别名含「我」，描述为「第一人称叙述者」），原规则只认名字「我」，于是叙述者的对白用了别的音色。改为名字、别名或描述任一表明是第一人称叙述者即用旁白音色
- 用真实模型合成了三份模拟样本（网文、含读音词典与各类数字的中文短篇、英式引号的英文短篇），ASR 校验、按章进度、开场结尾都正确

M5 中发现并修复的其他问题：

- **重新导入会丢失或重付已有的标注**：M4、M5 的文本规整改变了少数段落，提示词随之变化，逐块串行的角色表调用从第一个变化处起全部错过缓存。没有密钥时，重新导入会丢掉几乎所有说话人和角色；有密钥时会不经询问再花约 3 美元（同意是按地址只记一次的）。现在：没有回答的引语沿用上一次的机器结果（按顺序对齐，其次按文字），角色与音色一并保留；以前标注过的书先只用缓存，不够时先询问、给出费用估计，不同意（或非交互且无 `--yes`）就保留原有标注。在《春尽江南》工作目录的副本上验证：2044 句沿用，未知 5 句（原为 1 句），各角色台词数与原来一致；用真实密钥、不加 `--yes` 重新导入，没有产生任何调用
- **英文书**：「Chapter 1」读作 "Chapter One"、罗马数字章号，ASR 比对都会误判，现在两边都换成数字；`--title` 同时用于识别开头的书名行
- **章节标题、小标题、开场白**多是名字，ASR 常写成同音字（「青衫客」→「青山客」），重试无济于事：这些单元只检查句末是否丢字

### 6.5 音色库关卡（§9.1 Q11）

EXP-1 的试做音色全部满足以下条件，才进入 M3：

| 维度 | 标准 |
|---|---|
| 稳定性 | 每个音色随机合成 30 句（长短、情绪不同），盲听无明显音色漂移；与参考音频的说话人嵌入相似度不低于预置音色自身的基线（基线在实验中测定） |
| 可懂度 | 用 ASR 回转写，字错率不高于预置音色基线 + 1 个百分点 |
| 区分度 | 任意两个试做音色盲听可区分 |
| 口音 | 标准普通话，无方言或外国口音 |
| 速度 | RTF 不低于预置音色的 80% |

## 8. 约束与已知风险

| 风险 | 说明 | 应对 |
|---|---|---|
| **预置中文音色太少** | Qwen3-TTS CustomVoice 标准普通话预置音色只有 3 个，英文 2 个（设计文档 §5.6） | 内置音色库（CAST-1；英文 CAST-2 在第二阶段） |
| **库音色能否稳定复用** | 多角色能否进入第一阶段的决定性问题（§9.1 Q1） | ✅ EXP-1 已通过（§9.1 Q16） |
| **情绪变化时音色轻微漂移** | 强烈情绪（尤其哭腔、愤怒、耳语）下音色会变，听感「有点像换了人，但也可以理解为同一个人的不同情绪」，个别片段向预置音色靠近（设计文档 §5.6） | SCR-12 默认只用程度适中的情绪描述；若要根治，只能走微调（设计文档 §5.6 路线 D，不在第一阶段） |
| **库音色覆盖不全** | 固定的 12–20 个音色未必能贴合每个角色 | 选角表可手改；按书设计新音色列为 P2（CAST-12） |
| **情绪表达** | 情绪标签由 LLM 给出，标错或过度会损害听感 | SCR-12 可整体关闭 |
| **合成时长** | 30 万字约 7–8 小时（M1）；两个模型交替使用可能更慢 | 缓存续跑、按章节试听；按音色分组合成以减少切换 |
| **LLM 准确率** | 批量标注可能比逐句略降（设计文档 §7.2） | 对账 + 低置信度清单 + 手工修正 |
| **隐私** | 全书上传云端 LLM | LLM-5 提示；可用本地 LLM；SCR-13 无 LLM 模式 |
| **磁盘占用** | 缓存数 GB | CLI-6 |
