## 1. 背景与目标

### 1.1 项目总体目标

- **开源、公益**，暂不考虑任何商业诉求
- **中文优先**：第一阶段优先保障**现代白话中文**的质量。繁体中文书籍在朗读前自动转换为简体（只转换送给 TTS 的文字，原文不变），与简体书同等对待；文言或古白话成分较多的作品（如《红楼梦》），以及夹杂古文词汇的白话文，可能读错字或漂移到方言口音，这是 TTS 模型本身的问题，不在第一阶段的质量目标内（Q18、Q20）。英文书可以处理，但只用旁白一种音色（Q19）
- 许可证 **Apache-2.0**
- 差异化定位：**中文优先 + Apple Silicon 本地 TTS（MLX）+ LLM 多角色剧本化 + 标准有声书封装**（设计文档 §4.3）

### 1.2 场景路线图

| 场景 | 阶段 |
|---|---|
| **小说有声书** | **第一阶段，本文档范围** |
| 单人 / 多人播客音频制作 | 后续 |
| 复杂网页朗读 | 后续 |
| 学术论文（PDF）朗读 | 后续 |

**范围纪律**：播客、网页、论文在第一阶段只体现在 Script IR 的 block type 设计中，不写任何实现代码（理由见设计文档 §1.3）。

### 1.3 第一阶段目标

**用户在一台 Apple Silicon Mac 上，从源码运行 `huashuo` 命令，把一本中文小说（TXT / EPUB）变成一个可直接导入 Apple Books 的 M4B 文件：章节可跳转、元数据与封面齐全、旁白与主要角色由不同且合适的声音演绎、全书音量一致、没有漏读错读的整段文字。**

第一阶段的边界（Q26）：

| 方面 | 第一阶段 |
|---|---|
| 平台 | Apple Silicon Mac（M1 起，建议 16 GB 以上内存）；不支持 Windows 与其他架构 |
| 安装 | 只从源码安装，用户自建 Python 环境；没有安装包、不发布到 PyPI |
| 界面 | 只有命令行，界面文字只用英文（CLI-8） |
| 语言 | 中文书多角色；英文书由旁白一种音色朗读全书（Q19） |
| 播放器 | 只在 Apple Books 上验证（M4B-5） |
| 验证 | 仓库内的示例小说（金标准，§5.1）与项目负责人的试听；不在多种机器上做专门测试，由试用者反馈 |

「精心制作」具体指（第一阶段对「好」的定义）：

1. **结构正确**：章节与原书一致，章节名可读，播放器里能跳转
2. **内容完整**：原文每一个字都被读到，且只读一次；不读目录、版权页等非正文
3. **角色可辨**：旁白与主要角色声音不同，同一角色全书同一把嗓子，声音与角色的性别年龄相称
4. **听感舒适**：音量一致、停顿自然、没有爆音和明显的合成事故（复读、截断、静音）
5. **可修正**：说话人判错、读音错误、选角不满意时，用户能改一个文件然后只重跑受影响的部分

### 1.4 目标用户

第一阶段（预发布）的用户是**试用者与开发者**：

- 有一台 Apple Silicon Mac，能使用命令行、自己搭建 Python 环境
- 愿意配置一个 LLM API Key（云端或本地）以获得多角色；没有 Key 时也能做单一音色的有声书
- 不要求懂 TTS / LLM 原理；但愿意在需要时手工编辑结构清晰的文本文件（话本 / 选角表 / 读音词典），并反馈问题

## 2. 用户流程

```
huashuo make book.epub
  ① 导入    解析文件 → 正文、章节、元数据、封面；LLM 建角色表并标注说话人；自动选角
  ② 预估    章节数、字数、LLM 费用（导入前询问）、合成时长、磁盘占用
  ③ 审阅    （可选）查看/修改话本、选角表与读音词典，试听每个角色的声音
  ④ 合成    逐个合成单元，校验、重试，可中断、可续跑                （本地，小时级）
  ⑤ 封装    后期处理 + 章节标记 + 元数据 + 封面 → book.m4b          （本地，分钟级）
```

两种使用方式都支持：

- **一条命令跑到底**：`huashuo make`（或 `huashuo book.epub`），跳过 ③（CLI-2）
- **分步执行**：`import`、`audition`、`synth`、`package` 可单独运行，③ 之后的修改只触发必要的重算（CLI-3、SYN-3）

## 3. 功能需求

### 3.1 输入与解析（IN）

| 编号 | 需求 | 第一阶段 |
|---|---|---|
| IN-1 | 支持 **TXT** 输入，自动识别编码：UTF-8（含 BOM）、GB18030 / GBK、UTF-16；识别失败时明确报错，不静默乱码 | ✅ |
| IN-2 | 支持 **EPUB**（2 与 3）输入：按 spine 顺序读取正文，利用目录（NCX / nav）辅助章节划分 | ✅ |
| IN-3 | 从 EPUB 提取**元数据**（书名、作者、语言、出版者、简介、出版日期）与**封面图** | ✅ |
| IN-4 | TXT 无元数据时，从文件名与正文开头推断书名/作者；`--title`、`--author`、`--cover` 覆盖书名、作者和封面，重新导入时沿用。不提供配置文件 | ✅ |
| IN-5 | **语言自动识别**（中文 / 英文），可手动指定；决定章节规则、分句规则、TTS 语言参数 | ✅ |
| IN-6 | 中文书名、中文路径、带空格/特殊字符的路径全程可用（设计文档附录 B 的前三项陷阱不得重现） | ✅ |
| IN-7 | 支持 MOBI / AZW3 / FB2 等其他电子书格式（可借 calibre `ebook-convert` 转成 EPUB 后处理） | 后续 |
| IN-8 | 支持文本型 PDF 小说 | 后续 |

### 3.2 文本清洗与结构识别（TXT）

| 编号 | 需求 | 第一阶段 |
|---|---|---|
| TXT-1 | **章节识别（中文）**：「第X章/回/卷/部/节/集」（中文数字与阿拉伯数字）、楔子、序章、序言、尾声、终章、番外；支持网文无分隔符标题（「第一章陨落的天才」）；不误伤正文中的「他第一章都没看」 | ✅ |
| TXT-2 | **章节识别（英文）**：Chapter / CHAPTER + 数字或英文序数或罗马数字、Prologue、Epilogue、Part、Book 等 | ✅ |
| TXT-3 | **卷 / 章两级结构**：识别「第一卷 xxx」下的章节；M4B 章节名体现所属卷（如「第一卷 · 第三章 风起」），因为多数播放器只支持单层章节；故事集里带编号章节的篇名同样作为前缀 | ✅ |
| TXT-4 | **去除非正文**：目录页、版权页、EPUB 中的导航页、重复的书名页等不进入朗读 | ✅ |
| TXT-5 | **网文噪声清理**：常见的「求月票/求推荐票」、作者感言、「本章完」、站点水印与广告行，标记为 `skip`（不删原文，只是不读） | ✅ |
| TXT-6 | **引号识别**：`“”`、`「」`、`『』`、`""`、英式单引号 `‘’`（不误伤撇号），以及嵌套引号；归一化规则全书一致（设计文档附录 B 最后一项陷阱不得重现） | ✅ |
| TXT-7 | 全角/半角标点、空白、换行的规整：中文正文用全角标点，英文与数字用半角；借助成熟的 Unicode 库覆盖尽可能完整的中文标点（设计文档 §10.2）；不在中文里补半角句号 | ✅ |
| TXT-8 | 导入时列出识别结果：章节列表（标题 + 字数）与被跳过的内容；`make --dry-run` 只看计划不合成 | ✅ |
| TXT-9 | **编辑注释**：「注釋 / 注释 / 附注 / 译者注」等标签及其后直到下一章的内容标记为 `skip`（reason `notes`）；`--read-notes` 改为朗读，选择记在工作目录里 | ✅ |
| TXT-10 | **Project Gutenberg 声明**：`*** START/END OF THE PROJECT GUTENBERG EBOOK ***` 之外的首尾声明标记为 `skip`（reason `license`） | ✅ |
| TXT-11 | **从纯文本转换的 EPUB**：标记为标题、目录标签的内容必须「像标题」（短、不含句末标点、不以冒号结尾）才当标题；按固定宽度硬换行的正文先合并回段落；没有编号的篇名（短篇集）可识别为章节 | ✅ |

### 3.3 剧本化（SCR）

剧本（Script IR）是第一阶段的核心产物。格式名为「**话本**」，文件为 **JSONL**，扩展名 `*.huaben.jsonl`（Q5；格式定义见 [script-ir.md](script-ir.md)）。

| 编号 | 需求 | 第一阶段 |
|---|---|---|
| SCR-1 | 生成**人可读、可手改**的剧本文件：JSONL，一行一个 block；每个 block 有类型（chapter / heading / narration / dialogue / skip …）、文本、说话人（dialogue）、原文位置。写出时不转义非 ASCII 字符、字段顺序固定，保证能直接阅读和 diff | ✅ |
| SCR-2 | **旁白与对白切分**：一行里「他说："你好。"然后走了」拆成旁白 / 对白 / 旁白；对白标签（「他说」）归入旁白 | ✅ |
| SCR-3 | **角色抽取**：全书扫描得到角色表，每个角色含规范名、别名、性别、年龄段、简短性格/声音描述、台词数。性别与年龄段先只依据原文线索；原文没有线索的角色（厨师、飞行员、不写「他」「她」的第一人称叙述者）再用一次调用按身份、称呼、名字、描述与台词推断最可能的性别与年龄段，在 `cast.json` 中标为推断（`gender_inferred`、`age_inferred`），导入时列出，供选角与选旁白使用（Q27、Q28） | ✅ |
| SCR-4 | **别名归并**：「苏姑娘 / 苏晚晴」「贾宝玉 / 宝玉 / 宝二爷」合并为一人；「萧战 / 萧炎」这种同姓不同人不得误合并 | ✅ |
| SCR-5 | **说话人归属**：每一句对白归到角色表中的一个角色或「未知」；要能处理前置/后置/省略的对话标签、前向引用、被旁白打断的连续对白（设计文档 §3.2 的四类难例）。**「未知」一律由旁白声音朗读**，不设单独的兜底声音（Q10） | ✅ |
| SCR-6 | **段落级批量标注**：LLM 只输出「索引 → 说话人」，不回显原文；分块带上下文（设计文档 §7.2） | ✅ |
| SCR-7 | **对账**：切分得到的对白清单与 LLM 输出逐一核对，漏答、幻觉索引、未知角色名都要被发现并补问或标记；剧本拼接后的文本必须与清洗后的原文**逐字一致** | ✅ |
| SCR-8 | **不改写原文**：LLM 只做标注，不产出要朗读的文字；任何读法修改（`say`、读音词典）都是显式、可追溯的 | ✅ |
| SCR-9 | **第一人称小说**：以「我」为叙述者的小说，叙述者的对白用旁白音色，旁白按叙述者的性别选择（CAST-4） | ✅ |
| SCR-10 | 用户**手改剧本后重跑**，已改部分不被 LLM 结果覆盖 | ✅ |
| SCR-11 | **低置信度标注可见**：列出模型不确定的归属与所有「未知」说话人（`review.txt`），方便用户优先审阅 | ✅ |
| SCR-12 | **情绪/语气提示**：为对白标注情绪，合成时作为 TTS `instruct` 使用。情绪标签与说话人在同一次批量标注中产出（SCR-6），不额外调用 LLM；只用 7 个基本情绪（设计文档 §5.9）；`--no-emotions` 整体关闭 | ✅ |
| SCR-13 | **不用 LLM 也能出书**：没有 API Key 或选择 `--single-voice` 时，仍产出单一音色的有声书（只做章节与分段，不做角色） | ✅ |

### 3.4 选角与音色库（CAST）

**音色来源：内置音色库**（Q2）。项目预先设计、筛选并随项目发布一套**与输入无关**的固定音色，所有书都从这个库里选角；不在每本书处理时临时设计声音。

| 编号 | 需求 | 第一阶段 |
|---|---|---|
| CAST-1 | **内置中文音色库**：16 个经人工筛选的中文角色音色（男女各 8：儿童、少年、青年 ×2、中年 ×2、老年 ×2），另有 2 个专用旁白音色。每个音色带结构化标签（性别、年龄段、音色特征、适用角色）。全部为标准普通话，无方言口音 | ✅ |
| CAST-2 | **内置英文音色库**：同样的方式为英文建库；第一阶段的英文书由旁白音色朗读全书，包括对白（Q19） | 后续 |
| CAST-3 | **音色稳定**：同一库音色在任何书、任何句子上听起来是同一个人；库音色的生成方式固定、可复现（设计文档 §5.6） | ✅ |
| CAST-4 | **旁白音色**：专为旁白设计的库音色（中文 `narrator_female` 为默认，另有 `narrator_male`；英文暂用预置 `ryan`）。按书自动选择：第一人称的书按叙述者的性别，否则按明显的主角的性别，其余用默认（设计文档 §5.11）；`--narrator female\|male\|<音色>` 或手改 `cast.json` 覆盖；旁白音色不分给角色（Q3）；章节标题与开场/结尾报幕也使用旁白音色（Q7） | ✅ |
| CAST-5 | **按角色画像自动选角**：用完整画像（性别 + 年龄段 + 描述）匹配库音色标签，不把画像压成单一分数（设计文档 §3.3 的撞车问题不得重现）；先保证性别，再保证年龄：童声、少年与老年音色只给相应年龄的角色（Q28）；主要角色另参考 LLM 按描述给出的推荐 | ✅ |
| CAST-6 | **主要角色不撞声**：台词最多的前 8 个角色互不相同，且都不同于旁白 | ✅ |
| CAST-7 | **次要角色共享声音**：按性别/年龄段复用库音色，连续对话的两个角色不同声 | ✅ |
| CAST-8 | **同一角色全书一致**：跨章节、跨续跑、跨重新合成，同一角色的声音不漂移 | ✅ |
| CAST-9 | **预置音色不参与自动选角**：Qwen3-TTS 的预置音色（包括方言的 `dylan`、`eric`，以及会漂移到方言口音的 `serena`）只在用户于 `cast.json` 中手动指定时使用（Q21） | ✅ |
| CAST-10 | 生成**可编辑的选角表**：角色 → 音色，用户可改；修改后只重合成该角色的单元 | ✅ |
| CAST-11 | **试听**：为每个角色（或指定角色）用其一句真实台词生成样音，便于在长时间合成前确认选角；也可列出并试听整个音色库 | ✅ |
| CAST-12 | **按书设计新音色**：用户为某个角色写声音描述，临时设计一个库外音色，固化后在该书中复用 | 后续 |
| CAST-13 | 用户提供参考音频为某个角色**克隆声音**（需用户自行确保有权使用该声音） | 后续 |

### 3.5 读音与文本归一化（PRON）

| 编号 | 需求 | 第一阶段 |
|---|---|---|
| PRON-1 | **读音词典**：用户可为人名、地名、专有名词指定读音或替换文本（如「单于 → chán yú」「重楼」），全书生效；保存在工作目录的 `pron.txt` 中，不改原文、可追溯（设计文档 §10.3） | ✅ |
| PRON-2 | **数字、日期、单位、符号**的读法按语境处理（「1998年」「第3名」「5%」「3:2」）：TTS 自己读对的不动，只为读错的写法加读法 | ✅ |
| PRON-3 | 中文书里的英文单词/缩写、英文书里的中文名，能以合理方式读出。第一阶段交给 TTS 本身，只为字母加数字的写法（p2、4x5）加了读法 | 部分 |
| PRON-4 | 多音字错误可通过 PRON-1 的机制逐个修正（不要求自动消歧） | ✅ |

### 3.6 合成（SYN）

| 编号 | 需求 | 第一阶段 |
|---|---|---|
| SYN-1 | 默认引擎 **Qwen3-TTS 1.7B**，经 mlx-audio 在本机运行；模型可配置（`--model`） | ✅ |
| SYN-2 | **TTS 引擎是插件接口**：剧本不依赖具体引擎；第一阶段只实现 Qwen3-TTS，但接口不假设 HTTP | ✅ |
| SYN-3 | **按合成单元内容哈希缓存**：key 包含朗读文本、音色、instruct、模型与采样参数；改一个 block 只重合成它所在的单元（script-ir §6） | ✅ |
| SYN-4 | **断点续跑**：任意时刻中断（Ctrl-C、断电、崩溃）后继续，已完成部分不重做、不损坏 | ✅ |
| SYN-5 | **可复现**：同样输入与参数重跑，得到一致的音频（续跑不产生音色漂移） | ✅ |
| SYN-6 | **结果校验与重试**：检测空输出、截断、复读失控、时长与字数严重不符、语速异常；自动重试，仍失败则保留并在最后汇总报告，不中断整本 | ✅ |
| SYN-7 | **进度与预计剩余时间**：显示整体与当前章节进度 | ✅ |
| SYN-8 | 在内存允许时利用批量生成提升吞吐（mlx-audio `batch_generate`） | 后续 |
| SYN-9 | 按章节合成：可先只合成指定章节（`--chapters`）或开头一段（`--sample`）用于试听 | ✅ |
| SYN-10 | **ASR 校验**：每个合成单元用语音识别转写，与原文按读音比对；字错率超限或句末丢字时换 seed 重新合成（次数有上限），仍不通过则按 SYN-6 保留并报告。默认开启，`--no-asr` 关闭（省下约 5–10% 的合成时间） | ✅ |

### 3.7 音频后期（POST）

| 编号 | 需求 | 第一阶段 |
|---|---|---|
| POST-1 | **响度统一**：全书（含不同声音之间）响度一致，默认积分响度 **-18 LUFS**，`--loudness` 可改（Q6） | ✅ |
| POST-2 | **峰值控制**：真峰值默认 **≤ -1.5 dBTP**，无削波爆音；以前瞻限幅器只处理少数尖峰，响度仍达到目标 | ✅ |
| POST-3 | **停顿设计**：句间、同段内换说话人、段落之间、场景分隔（`***`、空行）、章节标题前后使用不同的停顿时长（script-ir §6），`--pause KIND=SECONDS` 可改；单个 block 可用 `pause_after` 覆盖 | ✅ |
| POST-4 | **首尾静音修整**：去除每个片段首尾多余的静音，再按 POST-3 统一插入 | ✅ |
| POST-5 | **章节标题朗读**：每章开头用旁白音色读出章节名，`--no-titles` 关闭；只由数字构成的标题读作「第X节」 | ✅ |
| POST-6 | **开场与结尾**：书开头用旁白音色读出书名与作者（`--credit` 附加「本有声书由话说 Huashuo 生成」），结尾有收束提示；均可关闭。作者名前的国籍或朝代标记读出来而不是照念括号：「[日]东野圭吾」读作「日本东野圭吾」，「（清）曹雪芹」读作「清代曹雪芹」；元数据保持原样 | ✅ |
| POST-7 | 拼接时采样率、声道、编码参数全书一致（设计文档 §8.5 的静音拼接坑不得重现） | ✅ |

### 3.9 LLM 接入（LLM）

**只支持 OpenAI 兼容的 Chat Completions 协议**，不写任何提供商专用的适配器（Q9）。这一个协议已覆盖 OpenAI、OpenRouter、DeepSeek、阿里云百炼（通义千问兼容模式），以及 LM Studio / Ollama / llama.cpp / vLLM 等本地服务。接入库使用 **pydantic-ai**（Q14，理由见设计文档 §6.5）。

| 编号 | 需求 | 第一阶段 |
|---|---|---|
| LLM-1 | 通过 **OpenAI 兼容接口**调用 LLM；模型名、API Key、Base URL 可配置（环境变量、当前目录的 `.env` 或 `~/.config/huashuo/env`，模型与地址也可用命令行），切换提供商只改配置不改代码 | ✅ |
| LLM-2 | 结构化输出有类型校验；校验失败时把错误回灌给模型重试，可重试错误与不可重试错误区分处理 | ✅ |
| LLM-3 | **执行前预估费用**（按两遍实际要发送的提示词计算，只计缓存之外的部分），执行中显示进度（每一遍的块数、已用请求与费用、已用时间），结束后显示实际 token 消耗与费用（本地模型费用为 0）。`import` 与 `make` 的最后是总结：总用时（`make` 分为导入、合成、封装）、本次 LLM 费用（请求数、缓存命中数）、待审阅的对白数，`make` 另列合成单元数、重试数与未通过检查仍保留的单元数 | ✅ |
| LLM-4 | **费用上限**：`--max-llm-cost`（默认 5 美元）是每次运行新花费的硬上限；第一遍之后若第二遍放不进上限，在第二遍开始前停下。被上限停下的导入照常完成，提高上限重新导入即可续跑，已完成的分块不重复付费 | ✅ |
| LLM-5 | **隐私与同意**：首次把一本书发往非本机的 LLM 端点时，明确告知「全书文本将发送给 <端点>」并征得同意（`--yes` 用于脚本）；续跑时缓存不够，先询问再付费 | ✅ |
| LLM-6 | **文本分析质量基准**：带人工标注的小型基准，用于比较不同模型的说话人归属准确率与成本；默认模型按基准结果选定为 **gpt-6-sol**（Q17，设计文档 §7.2.1） | ✅ |
| LLM-7 | 降低重复成本：LLM 的回答按提示词缓存在工作目录里，重新导入同一本书不再付费；提示词把角色表与指令放在最前，便于服务端的前缀缓存 | ✅ |
| LLM-8 | 支持 OpenAI Batch API 进一步降低成本 | 后续 |
| LLM-9 | **经济档**：`--llm-model gpt-6-luna`（30 万字约 0.15 美元的量级）。EXP-2 中它在常规对白上与 gpt-6-sol 一样准确，只在需要推理的无标签轮流对白上出错 | ✅ |

## 8. 约束与已知风险

| 风险 | 说明 | 应对 |
|---|---|---|
| **情绪变化时音色轻微漂移** | 强烈情绪下音色会变，「有点像换了人，但也可以理解为同一个人的不同情绪」（设计文档 §5.6） | 只用 7 个基本情绪；`--no-emotions` 可整体关闭 |
| **偶发的口音漂移与错读** | 自动校验抓不到口音；古白话、文言词汇容易读错（设计文档 §5.8） | 只用经过口音试听的库音色（Q21）；`huashuo redo` 按时间点重做；读音词典 |
| **库音色覆盖不全** | 16 个音色未必贴合每个角色；角色多的长篇里配角会共享音色 | 选角表可手改；按书设计音色在后续阶段（CAST-12） |
| **LLM 准确率** | 批量标注可能出错，便宜模型的自报置信度不可靠（设计文档 §7.2.1） | 对账 + `review.txt` + 手工修正 |
| **LLM 成本** | 角色众多的长篇约 10 美元 | 预估、硬上限、可续跑（LLM-3、LLM-4）；本地 LLM；`--single-voice` |
| **隐私** | 多角色需要把全书发给 LLM | 首次发送前征得同意（LLM-5）；可用本地 LLM；`--single-voice` 不发送 |
| **合成时长与磁盘** | 30 万字约 7–8 小时（M1）；缓存数 GB | 缓存续跑、按章节试听；`huashuo clean` |
| **依赖私有接口** | 库音色注入依赖 mlx-audio 0.5.5 的私有方法，版本锁定 | 后续向上游提交正式接口（§7） |

| Q27 | 原文没写性别的角色怎么办（2026-09-27，示例小说《广告》） | **单独推断，标为推断**。角色表那一遍只依据原文线索，没有线索就是 unknown；这很常见（《白夜行》159 个角色中 24 个），而 unknown 的角色选角时不看性别，音色的性别等于随机，第一人称叙述者性别不明时旁白也只能用默认。第二遍之后，只把性别不明的角色（带描述与几句台词）交给 LLM 推断最可能的性别，或回答 group（群体）、unknown；结果写进 `cast.json`，标 `gender_inferred`，导入时列出。没有改动原有提示词，已缓存的回答仍然有效；以前标注过的书只缺这一次调用，续跑时照常先询问 |
| Q28 | 选角时年龄有多重要（2026-09-28，《广告》试听） | **性别第一，年龄第二，然后才是分散**。《广告》里原文没写年龄的空军飞行员分到嘶哑缓慢的 `old_man_hoarse`，听起来太老：当时年龄每差一档只算 20，年龄未知时用老年音色只算 35，都低于「与对话的人同声」的 40。改为：(1) Q27 的那次调用一并推断原文没写的年龄段，标 `age_inferred`（《白夜行》159 个角色中 77 个年龄不明，推断为中年 41、青年 36），提示词不变、缓存仍有效；(2) 童声、少年、老年这些特征鲜明的音色给其他年龄的角色代价 90；成年音色之间，偏老一档 25、偏年轻一档 20（宁可年轻）；(3) 对话的人同声的代价升为 100。于是次序是：性别 > 与对话的人不同声 > 年龄 > 分散。《白夜行》上特征鲜明的音色配错年龄由 48 人降到 3 人，都是合适的音色全被对话的人或主要角色占用；一个在长篇里长大的角色只有一个年龄（桐原亮司标为少年，用少年音色），由 `cast.json` 手改（设计文档 §8.7） |
| Q29 | 功能冻结后加 MP3 导出（2026-09-28） | **例外加入**（M4B-7）。试用者手机上未必有能播 M4B 的播放器，按章 MP3 在任何播放器里都能逐章听。它只在最后打包这一步：同一段 PCM 换一个编码器，不改变合成、不影响已有的书，默认格式不变。README 的在线试听另行解决：GitHub 的 README 不能嵌入音频（MP3 也不行），只能用通过编辑器上传的 MP4 视频（封面静图加音频片段）；完整的 M4B 与按章 MP3 作为预发布版的附件下载 |
